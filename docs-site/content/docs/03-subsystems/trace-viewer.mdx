## 系统定位

Trace Viewer 是 TraceHound 平台最核心的数据子系统。它提供**分布式调用链的采集、存储、检索与可视化能力**，同时通过 MCP 接口向诊断 Agent 暴露结构化的调用链数据。

### 核心能力

- 以**树状结构**展示单次请求的完整调用链，包含嵌套层级和调用关系
- 区分**同步调用**（计入用户延迟）与**异步调用**（不计入）
- 自动计算**关键路径**（Critical Path）和**瓶颈 Span**
- 支持**当前值与历史基线的对比分析**
- 通过 TraceID ↔ 业务ID 双向关联实现**全息排查**

### 与鹰眼的关系

Trace Viewer 的设计参考了阿里鹰眼（EagleEye）的核心可视化理念——树+时间轴混合视图。但与鹰眼不同的是，Trace Viewer 双模输出：

- **Web 控制台**：SRE 人工排查用的可视化界面
- **MCP 接口**：诊断 Agent 调用的结构化数据接口

## MCP 工具接口

### `trace_search` — 搜索异常 Trace

搜索指定时间范围内、满足条件的 Trace 摘要列表。默认按耗时降序排列。

```typescript
trace_search(params: {
  time_range: TimeRange;
  scope: {
    service: string;  // 必填：入口服务名
    cluster?: string;
  };
  filters?: {
    min_duration_ms?: number;   // 最小耗时过滤
    max_duration_ms?: number;
    has_error?: boolean;       // 是否包含错误
    status_code?: string;      // HTTP 状态码
    operation?: string;        // 操作名模糊匹配
  };
  pagination?: PaginationParams;
}) → ListResponse<TraceSummary>

// 返回
interface TraceSummary {
  trace_id: string;              // 全局唯一 TraceID
  total_duration_ms: number;     // 总耗时
  span_count: number;            // Span 数量
  entry_service: string;         // 入口服务
  entry_operation: string;       // 入口操作
  bottleneck_span: {             // 耗时最长的 Span
    service: string;
    operation: string;
    duration_ms: number;
    percentage: number;          // 占总耗时百分比
  };
  error_spans: {                 // 异常 Span 列表
    span_id: string;
    service: string;
    error_message: string;
  }[];
  start_time: string;            // ISO 8601
}
```

### `trace_get_detail` — 获取调用链详情

获取单条 Trace 的完整调用链树。

```typescript
trace_get_detail(params: {
  trace_id: string;
}) → DetailResponse<TraceDetail>

interface TraceDetail {
  trace_id: string;
  total_duration_ms: number;
  start_time: string;

  spans: SpanNode[];            // 调用链树（树状结构，含父子关系）

  critical_path: {              // 关键路径（入口 → 瓶颈 Span 的最短路径）
    span_ids: string[];
    total_duration_ms: number;
    bottleneck_span_id: string;
  };

  // 全局时间轴：每个 Span 在时间轴上的位置
  timeline: {
    span_id: string;
    start_offset_ms: number;   // 相对 Trace 起点的偏移
    duration_ms: number;
  }[];
}

interface SpanNode {
  span_id: string;
  parent_span_id: string | null;
  service: string;
  operation: string;
  call_type: 'sync' | 'async';  // 同步/异步
  duration_ms: number;
  start_offset_ms: number;
  status: 'ok' | 'error';
  error_message?: string;
  children: SpanNode[];          // 子 Span（递归嵌套）
  tags: Record<string, string>;  // 如 db.statement, http.url
}
```

### `trace_compare_baseline` — 基线对比

将当前 Trace 的各 Span 耗时与历史正常基线对比。

```typescript
trace_compare_baseline(params: {
  trace_id: string;
  baseline: 'same_hour_yesterday' | 'last_5min_normal' | 'auto';
}) → CompareResponse<TraceSpanComparison>

interface TraceSpanComparison {
  trace_id: string;
  spans_comparison: SpanDeviation[];
  overall_verdict: {
    is_anomalous: boolean;
    anomaly_spans: string[];     // 偏差超过阈值的 span_id 列表
    primary_suspect: string;     // 最可疑的 span_id
  };
}

interface SpanDeviation {
  span_id: string;
  service: string;
  operation: string;
  current_duration_ms: number;
  baseline_duration_ms: number;
  ratio: number;                 // current / baseline
  is_anomaly: boolean;
}
```

### `trace_get_span_detail` — Span 详情下钻

获取单个 Span 的详细信息，包括具体操作内容、线程栈等。

```typescript
trace_get_span_detail(params: {
  trace_id: string;
  span_id: string;
}) → DetailResponse<SpanDetail>

interface SpanDetail {
  span_id: string;
  trace_id: string;
  service: string;
  operation: string;
  call_type: 'sync' | 'async';
  duration_ms: number;
  start_time: string;
  host: string;                  // 执行主机 IP
  status: 'ok' | 'error';
  error_message?: string;

  // 根据 Span 类型展示具体操作内容
  operation_detail?: {
    type: 'sql' | 'http' | 'rpc' | 'cache' | 'mq';
    // SQL 类型
    sql_statement?: string;
    sql_rows_scanned?: number;
    sql_rows_returned?: number;
    sql_index_used?: string;
    // HTTP 类型
    http_method?: string;
    http_url?: string;
    http_status_code?: number;
    // RPC 类型
    rpc_method?: string;
    rpc_service?: string;
    // Cache 类型
    cache_command?: string;
    cache_key?: string;
    // MQ 类型
    mq_topic?: string;
    mq_operation?: 'produce' | 'consume';
  };

  thread_stack?: string;         // 线程栈（如果有采样）

  related?: [
    { label: '查看同服务同操作的 Span 基线', tool_name: 'trace_compare_baseline', params: {...} },
    { label: '查看宿主机的 CPU/内存', tool_name: 'host_get_metrics', params: {...} },
  ];
}
```

### `trace_get_topology` — 服务调用拓扑

获取指定服务或全局的调用拓扑图。

```typescript
trace_get_topology(params: {
  scope?: { service?: string; cluster?: string };
  time_range: TimeRange;
}) → DetailResponse<TraceTopology>

interface TraceTopology {
  nodes: {
    service: string;
    type: 'http' | 'rpc' | 'db' | 'cache' | 'mq';
    has_error: boolean;
    avg_duration_ms: number;
  }[];
  edges: {
    from: string;
    to: string;
    call_count: number;
    has_error: boolean;
    avg_duration_ms: number;
  }[];
}
```

## Agent 消费模型

```
Step 1: trace_search("order-service", {min_duration_ms: 1000})
  → 拿到 Top 20 慢 Trace 摘要
  → 每个 Trace 摘要已标注 bottleneck_span

Step 2: trace_compare_baseline(anomalous_trace_id)
  → 确认哪些 Span 偏离基线
  → 主要嫌疑 Span 已自动标注

Step 3 (可选): trace_get_detail(trace_id)
  → 需要展示给 SRE 看时才拉完整调用链树

Step 4 (深挖): trace_get_span_detail(trace_id, bottleneck_span_id)
  → 查看具体 SQL/线程栈/宿主机
```

## 关键设计决策

| 决策 | 理由 |
|------|------|
| **接口层自动标注瓶颈 Span** | Agent 上下文窗口有限，不应让 Agent 做"遍历所有 Span 找最大耗时"的机械计算 |
| **对比接口独立拆分** | 基线对比是诊断的核心能力，作为独立接口可以单独优化缓存和算法 |
| **Span Detail 支持 related 提示** | 引导 Agent 的下一步下钻方向，减少无效探索 |
| **拓扑接口返回聚合数据** | Agent 先看宏观调用关系再深挖，符合人类排查思维 |
