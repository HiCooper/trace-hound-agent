## 系统定位

**TraceHound** 是一个基于 AI Agent 的智能故障定位平台。它在传统监控告警体系之上，利用大语言模型的推理能力，将 SRE 从"告警 → 手动排查 → 定位根因"的繁重流程中解放出来。

### 一句话定位

> **传统监控负责发现问题，TraceHound 负责解释问题。**

监控告警系统（Prometheus、Grafana、ELK）在检测异常上已有成熟的毫秒级能力。TraceHound 不替代它们，而是在告警触发后介入，完成多源数据关联、因果推理、诊断报告生成的完整闭环。

### 核心场景

| 场景 | 触发条件 | 核心价值 |
|------|---------|---------|
| 服务 RT 异常飙升 | p99 延迟突增 | 自动定位调用链瓶颈 Span |
| 服务报错突增 | 5xx / 异常率升高 | 错误聚类 + 变更关联 |
| CPU 水位飙高 | 主机/容器 CPU 超阈值 | 进程→线程→热点方法定位 |
| 网络重传率偏高 | TCP 重传率异常 | 机器间对比 + 网络层分析 |

### 设计原则

1. **告警驱动，Agent 介入** — 不做实时数据监听，由传统告警回调触发诊断
2. **白盒推理** — 每一步排查逻辑、每一条证据都对用户可见、可质疑、可纠偏
3. **经验闭环** — 每次诊断结果沉淀为结构化病例，下次类似告警可直接检索复用
4. **人机共享数据层** — 诊断 Agent 和 SRE 消费同一套 MCP 工具接口，同一份真相
5. **场景化 Skill 拆分** — 不同故障类型有独立的诊断 Skill，独立迭代
